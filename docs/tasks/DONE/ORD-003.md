ORD-003 - Order Status Management
Bạn là AI backend engineer phụ trách ORD-003: Order Status Management cho LanoCRM.
1. Bối cảnh
Dự án: LanoCRM - Orders Module
Task: ORD-003: Order Status Management
Phase: Phase 2 - Customers & Orders
Mục tiêu: Implement API đổi trạng thái đơn hàng + inventory hooks theo workflow SHIPPING/POS.
2. Tài liệu phải đọc trước
00_INDEX - Order Workflow Documentation: mô tả 5 task backend (PAY-001, INV-001, ORD-003, RETURN-001, RETURN-002).
SHIPPING_FLOW - SHIPPING Orders Workflow.
ORDER_RULES - Order Validation Rules.
ORDERS_TABLE - Orders Table Schema.
INVENTORY, DATA_INTEGRITY, CONCURRENCY - các edge cases quan trọng.
3. Yêu cầu chính
Implement service OrderStatusService với hàm trung tâm, ví dụ: changeStatus(int $orderId, string $toStatus, array $payload = []): array.
Hỗ trợ đầy đủ các transition hợp lệ theo docs SHIPPING_FLOW (POS vs SHIPPING).
Gọi inventory hooks đúng thời điểm (trừ kho, hoàn kho nếu cần) theo rules.
Ghi log vào order_status_logs cho mỗi lần đổi trạng thái.
API endpoint chuẩn REST: PUT /api/orders/{id}/status.
Response JSON phải chứa đủ: success, message, data (order sau khi update), và nếu có, warnings.
4. Chi tiết implementation
Service layer (bắt buộc)
Không viết business logic trong Controller.
Service chịu trách nhiệm:
Validate transition từ trạng thái hiện tại sang trạng thái mới.
Gọi repository cập nhật trạng thái.
Gọi inventory service khi cần.
Ghi status log.
Phải dùng transaction DB cho các bước cần tính toàn vẹn (update order + inventory + logs).
Repository layer
Viết repository riêng cho Orders (nếu chưa có pattern chuẩn) theo kiến trúc Controller → Service → Repository → Model.
Cần có hàm:
findByIdForUpdate($orderId) nếu dùng pessimistic lock, hoặc pattern an toàn tương đương theo docs CONCURRENCY.
updateStatus($orderId, $toStatus, array $extra = []).
Status rules
Không cho nhảy status tự do, chỉ cho phép các transition được docs approve.
Với POS orders: flow đơn giản hơn (có thể skip một số bước), nhưng vẫn phải đảm bảo inventory & payment logic không bị conflict.
Inventory hooks
Khi nào trừ kho, khi nào hoàn kho, bám đúng quy tắc trong docs INVENTORY + ORDER_RULES.
Tránh double-deduction hoặc overselling bằng cách sử dụng transaction + pattern đã mô tả ở CONCURRENCY.
5. Testing
Viết unit tests cho OrderStatusService:
Transition hợp lệ (draft → confirmed → processing → shipping → delivered → completed).
Transition không hợp lệ (ví dụ: draft → completed trực tiếp) phải throw exception hoặc trả về lỗi rõ ràng.
Viết integration tests cho endpoint PUT /api/orders/{id}/status với DB thật:
Happy path cho cả POS và SHIPPING orders.
Cases cancel/rollback nếu docs có mô tả.
6. Definition of Done cho ORD-003
Service, Repository, Controller đã implement theo clean architecture.
Status workflow hoạt động đúng theo SHIPPING_FLOW/ORDER_RULES.
Inventory hooks đã gắn đúng điểm.
Unit + integration tests pass (theo PHPUNIT-QUICK-START).
Không phá vỡ các endpoint Orders hiện có.
